- Added a Rust workspace with a small Hello native add-on, SDK manifest and bounded protocol test host using the pinned Toolboks SDK, shared UI, protocol and catalog crates.
- Added Windows PR checks and per-add-on tag releases with main-ancestry/version validation, tests of the release executable, SHA-256 assets and executable size reporting. Expected tag-rejection tests finish with a successful CI exit code. Build credentials stay read-only.
- Added release-driven catalog PR automation using the host's format and compatibility metadata. Catalog publication requires owner review; a repository-scoped CATALOG_PR_TOKEN is required for bot PRs. The catalog now uses the owner's plain-list format: no signatures, keys, sequence numbers or validity dates. The empty catalog and tooling match host PR #134.
- Added Disk Manager as an independent `disk-manager.exe`, keeping its ID, five pages, scan/map/ranking behavior, preference keys and data location. It uses the pinned SDK runtime and shared styling. Suspending cancels scans and releases results while exports and analysis can finish in the background.
- Catalog generation now copies optional `host-services.json` page names and background behavior, preserving Disk Manager page links. Added `addon-repo measure <name>` for release executable size, first-frame timing and Windows idle memory. Add-on builds use the host's static CRT and System32 DLL-load restriction.

Release blockers:
- Defrag, TRIM, Windows-selected optimization and fragmentation analysis go through the host's administrator helper (protocol 3): a separate elevated process shows its own Confirm / Cancel window and applies the change only after Confirm. Host dependencies are pinned to host staging with protocol 3 and the unsigned catalog. Still pending before release: the dialog in a real window and a real UAC and drive test, and the GUI install test with screenshots.
- Added Memory Cleaner as an independent `memory-cleaner.exe`, keeping its ID, Home and Advanced pages, trimming, automatic cleaning and guided tour. The cache purge now goes through the host administrator helper (separate window with Confirm / Cancel) instead of restarting the whole app as administrator. The built-in copy in the host stays until the final removal step.
- Added Event Watch as an independent `event-watch.exe`, keeping its ID, Live, Crashes and Summary pages, event and crash analysis, and guided tour. It only reads Windows event logs and crash dump headers, with no administrator rights. The built-in copy in the host stays until the final removal step.
- Added Resource Monitor as an independent `resource-monitor.exe`, keeping its ID, Overview, Details, Processes and Connections pages, graphs, process actions and guided tour. It needs no administrator rights. The built-in copy in the host stays until the final removal step.
- Removed the pull request CI workflow. Checks (format, clippy, tests, validation and the release executable tests) run locally before merging. The tag-driven release workflow is unchanged.
- Added Audio Gainer (Aural) as an independent `aural.exe`, keeping its ID, settings key, live audio behavior and background monitoring. `addon-repo` now treats the `pages` and `background` keys of `host-services.json` as optional. The built-in provider in the host stays until the final removal step.
- Added Macro Manager as an independent `macro-manager.exe`, keeping its ID, Editor and Mouse editor pages, settings, recording, hotkeys and playback. Because it now runs in its own process, keys typed in the Toolboks window are skipped by recognising the Toolboks process, and the click on "Stop recording" is removed from a macro by checking what was under the cursor once recording stops. The built-in provider in the host stays until the final removal step.
- Every moved add-on now applies the Toolboks look (fonts, text sizes, spacing) when it first draws. Real-window checks showed that an add-on process has no fonts of its own, so Event Watch, Memory Cleaner, Resource Monitor, Aural and Macro Manager drew their text as empty boxes. The pin moved to the host commit that also loads Consolas for fixed-width text.
- Added Debloater as an independent `debloater.exe`, keeping its ID and five pages. Everything that needs no administrator rights works as before; items that need administrator rights are listed but cannot be changed until the protocol 3 administrator helper operations exist. The built-in tool in the host stays until the final removal step.
- Added System Profiles as an independent `system-profiles.exe`, keeping its ID and Gaming page. Applying and restoring a profile go through the protocol 3 administrator helper (a separate window with Confirm / Cancel) instead of restarting the whole app as administrator. The built-in provider in the host stays until the final removal step.
- Debloater: the Privacy and ads items that need administrator rights, the restore point switch and undo of such a run now go through the protocol 3 administrator helper (a separate window with Confirm / Cancel). Services, Tasks and administrator startup entries are still off.
- Debloater: switching services and scheduled tasks, the restore point switch on those pages, and their undo now go through the protocol 3 administrator helper (a separate window with Confirm / Cancel). Administrator startup entries are still off.
- Debloater: all-users startup entries and their undo now go through the protocol 3 administrator helper. With this, every Debloater change that needs administrator rights works in the add-on through a separate confirmation window.
